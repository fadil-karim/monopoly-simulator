The site is now a public viewer with a database behind it, released as v1.3 on main. The games are played by a runner on your machine with your keys and streamed in as they happen; nothing a visitor does spends anything.

How it fits together. The runner (`runner/run.mjs`) plays games with the existing engine and AI layer, registers each game with the site, and flushes every event and model call every 700 ms, so viewers see a move within a second or two. At the end it posts the result, each player's rank, cash and net worth, their income by source and property, their dice, and their call statistics, plus a match summary and, if you give it a narrator model, a written match report. The Worker keeps all of it in D1: one row per game, per seat, per event and per model call, with the provider, the exact model id, the effort, and the model id the API itself reported back on every call. The viewer rebuilds any moment of any game from the stored log with a reducer that is checked against the engine after every event of 80 games, so a replay is the game as it was played.

What visitors get, by tab. Live shows the game being played, following along, or the latest game when the table is quiet, and picks up the next game by itself. Games lists every game; each opens with a replay: step back and forth with the arrows, play at one, four, fifteen or sixty events a second or a turn a second, drag to any moment, jump to the end. Under every game, "What happened" carries the narrator's report, a transcript of the whole game as plain text to paste into any AI (full or short), the full log as JSON, and, when you switch the narrator on, a box to ask the game questions. Monopoly stats is the board across all games: length, goes, trades, auctions, bankruptcies, buildings, the money flows, the dice against the two-dice expectation, a heat board of where the tokens land, the most landed-on squares, rent by square and by colour group, and a table of every property. Model stats is every model's record: games, wins, win rate, average rank and net worth, bankruptcies and when, rent in and out, purchases, auctions, trades, buildings, jail, table talk, calls a game, fallbacks, illegal decisions, latency, tokens per call and its own dice.

The eight seats are in `runner/config.example.json`: Claude, ChatGPT, Gemini, Grok, Kimi, Mimo, GLM and Mistral, each with a model id and effort you can change. Moonshot, Z.ai and Xiaomi are new providers, all OpenAI-compatible; their endpoints and model ids come from third-party integration docs rather than the vendors' own pages, so check them against your console before the first real game. The example keeps Gemini at 2.5 Pro and ChatGPT at gpt-5 from the existing lists.

Three things only you can do, in order. Create the database with `npx wrangler d1 create monopoly-ai`, paste the id into the commented block in `wrangler.jsonc`, uncomment it, run `npm run migrate`, and push. Set the runner token with `npx wrangler secret put RUNNER_TOKEN`. On the machine with the keys, copy the example config to `runner/config.json`, put the keys, the site address and the token in `runner/.env`, and run `node runner/run.mjs --loop`. Until the database exists the deploy still succeeds and the site says the database is not set up yet. The narrator box is off until you set `NARRATOR_API_KEY`; the README has the rest, including the API.

One cost to know about: while a game runs, each open viewer polls the site every two seconds, around forty requests a minute. A handful of viewers fits the Workers free tier; a crowd watching all day wants the paid plan.

Verified before the push: the reducer against the engine at 272,000 comparison points across both editions; the engine check (illegal 0); the Worker and runner end to end against a local database, two bot games streamed in and read back through every route, with the stored log replaying to the stored result; the viewer in headless Chromium through the live tab, the replay controls, the games list, both statistics pages, a bot game followed live from start to finish, and the phone layout; the dry-run deploy with the Worker bundled; and the rendered pages.
