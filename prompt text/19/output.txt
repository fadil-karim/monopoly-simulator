The token the runner sent didn't match the one saved on the site. v1.18 makes that harder to get wrong and easier to fix, and it goes live as soon as Cloudflare finishes deploying it.

What changed:
- **Spaces and line breaks around the token are ignored.** Copying a token from Terminal often brings a line break with it. If that's what happened, the next Start simply works.
- **The token is checked before a game starts.** On that last run the game had already begun when the site refused the token, so a call or two to the models may have gone out. Now a refused token stops everything first.
- **A refusal says which token was sent.** The message names where the runner got it, such as the dashboard's token box or the runner/.env file, and how many characters it has. A token made with the openssl command has 64.

Pull the update and start the dashboard again, then press Start:

```
cd ~/monopoly-simulator
git pull
npm run dashboard
```

If the token is still refused, set a fresh one in both places:
1. Make one in Terminal:

   ```
   openssl rand -hex 32
   ```

2. In Cloudflare, open the monopoly-simulator Worker, then Settings, then Variables and Secrets. Edit RUNNER_TOKEN, paste the new value and choose Deploy.
3. Paste the same value into the dashboard's token box, tick "remember" and press Start.

Verified before the push:
- A wrong token from the token box, from the runner/.env file and from the command line each stopped the runner before any game began, naming the source and the length.
- A site whose secret carries a trailing space accepted the token and played a game through.
- The viewer suite, the provider tests, the simulator, the replay check, the deploy dry run and two bot games all pass.
