v2.0 is pushed to `main`. The simulator now runs on its own, apart from the website.

**The simulator, in its own container**
- `Dockerfile` and `docker-compose.yml` package the game engine, the AI prompting and the runner, without the website. Its games, table and keys live in a Docker volume that rebuilds and updates leave alone.
- **On your Mac:** run `docker compose up -d --build`, then open http://127.0.0.1:8788. It's the same dashboard as before.
- **On a cloud instance:** copy `simulator.env.example` to `simulator.env` and fill in the keys and `RUNNER_TOKEN`. Then run `MONOPOLY_MODE=play docker compose up -d --build` to play batch after batch with no dashboard. For the dashboard there, use an SSH tunnel.
- Running from the repo (`npm run dashboard`, `node runner/run.mjs`) still works with your existing `runner/.env` and `runner/config.json`.

**The data is stored independently**
- Every game is written to the simulator's own store as it's played: every event, and every model call with its full prompt. The site gets a copy.
- If the site is down, mid-deploy, or refusing the token, the game carries on, and the site catches up when it's back. I tested this by taking a local site down mid-game.
- A push to `main` now only updates the website. The simulator changes only when you rebuild its image. To update it without cutting a game short, press **Stop after this game** first.
- If the site's database is ever lost or replaced, `republish` refills it from the store. A game only ever goes to the site it was played for, so local test games can't reach the public site.
- One thing to run once: `docker compose run --rm simulator import-site` copies the games already on the site into the store, so it holds the whole history.

**No heuristics**
- A model that gives no valid answer forfeits that one choice. That covers a failed call, no JSON, an empty `{}`, or an answer that breaks the rules. The engine takes the option that does nothing: nothing before the roll, no purchase (so the property goes to auction), or a bid of nothing.
- The turn still goes on. The token rolls and moves as always (that was never the model's choice), and rent, tax and cards are paid. If it owes money and gives no plan, the bank's forced sale mortgages, then sells buildings, before bankruptcy.
- A trade offer it doesn't answer properly is rejected by default. The log records the forfeit with what went wrong, then the rejection with its reason, and the trades ledger shows "rejects it by default".
- A model without its key is now left out of the pool rather than played by the bot. The bot only plays seats you configure as bots.

**Turn times**
- Every turn is timed, from the question before the roll to the end of the turn, including waiting on other players' answers.
- Each player's card shows their average turn and forfeits. The model stats gain "Forfeits / game" and "Time a turn".
