Done and released as v1.19 (pushed to main, so it's deploying now).

**The ledgers, at the bottom of every game.** They follow the move shown, live or in a replay.
- **Payments**: a table of who paid whom (every player and the bank), then every payment newest first, with what it was for: rent, passing GO, taxes, cards, purchases, auctions, buildings, mortgages, jail fines, cash in trades and bankruptcies. You can filter by player and by kind. The books balance: each player's cash is always their starting cash plus what they received less what they paid.
- **Trades and offers**: every trade offered, with each counter-offer and answer, the reasons the models gave, and how it ended. That's completed (with what changed hands), rejected, lapsed after too many counter-offers, or refused by the rules, such as offering a property that wasn't theirs to give.
- **Properties**: each property's owner and buildings, landings, rent collected, rent per landing, what it first sold for, what its buildings cost, how often it was mortgaged and traded, how many players have held it, and rent less cost. Click any heading to sort.

**Also in this release**
- **Roll charts**: rest the pointer on a bar of any roll chart (the board's centre, a player card or the statistics pages), or tap it on a phone. It says, for example, "7 rolled 86 times out of 565 rolls · 15.2%", beside the 16.7% two fair dice would give. Moving into the middle of the board now brings the match figures back, so that chart can be hovered at all.
- **Tokens**: each model's token wears its maker's logo in a ring of the player's colour. Kimi's sits on a black tile, as Kimi draws it. MiMo uses Xiaomi's orange "mi", because the MiMo wordmark can't be read at token size. The rule-based bot keeps its initial.
- **Dashboard**: the model box in each row, and the narrator's, is now a dropdown. Before a key is in, it lists the models the dashboard already knows, with their names. Once a provider's key is in, it lists every model the provider serves to that key, grouped by maker. "Other" still takes any id.

The dashboard and the runner run from your Mac's copy of the repository, so `git pull` there and restart the dashboard to get the dropdowns. Games played after that also record counter-offers properly. Until now a counter-offer overwrote the game's round, so it showed as round 1 in the feed. The site now reads old games with the right round as well.

**Running without your MacBook** (advice only, nothing changed)
Your data is already online. Every move is written to the site's database at Cloudflare as it happens. What still needs the Mac is the runner, which plays the games with your keys. While the Mac sleeps, nothing is played. A game cut off that way stays marked as running, and the Live tab shows it frozen until the next game starts.

I'd move the runner, as it is, to a small always-on server:
1. Rent the smallest cloud server from Hetzner or DigitalOcean, a few pounds a month, and install Node 22.
2. Clone the repository there and put your keys, the site and the token in `runner/.env`.
3. Run `node runner/run.mjs --loop` as a systemd service, so it starts again after a crash or a reboot. To change the table, edit `runner/config.json` there and restart the service.
4. Or, instead of the service, run the dashboard there and reach it through an SSH tunnel: `ssh -L 8788:127.0.0.1:8788 you@server`, then open http://127.0.0.1:8788 as now. It listens only on the server itself, so the page and your keys stay off the internet.

Nothing on the site changes, and the model calls cost the same. Updating the runner is a `git pull` and a restart between games.

The step after that, if you want no machine at all, is to play the games inside Cloudflare. Each game would run in a Durable Object, calling the models with your keys stored as Worker secrets and writing straight to the database, started on a schedule or from a button. The catch is that every push to main redeploys and would cut off a game in progress. So the engine would first have to pick a game up from its saved state, which is a few releases of work.

On backups: `runner/out/` keeps a full copy of each game, prompts included, on whichever machine runs the runner. That folder could go to an R2 bucket at Cloudflare instead. The database can be exported whenever you like with `npx wrangler d1 export monopoly-ai --remote --output=monopoly.sql`.
