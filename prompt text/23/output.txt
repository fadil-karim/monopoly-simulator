The game itself is sound; three of the eight seats were not. Fixes are released as v1.22, but they only reach your Mac once you pull and restart the runner.

**Is the game working, and is GO paying out?** Yes. I replayed all 559 events of game `20261016-e34x-1` (8 rounds so far):
- **GO:** all 7 laps paid £200, including a Chance card that took DeepSeek past GO.
- **Rent:** all 22 rents follow the rules (station counts, the doubled rent on a full set, DeepSeek's houses on the orange set).
- **Cash:** every player's cash matches the payments after every event, so no money appeared or vanished. Taxes, jail, cards, auctions and even building also check out.
- The game started at 17:18 UTC, before v1.19, so it runs the older engine. That only changes how counter-offers are numbered, and the site reads both.

**Why models drop to the bot.** 33 fallbacks in this game, from four causes:

1. **ChatGPT, Grok and Kimi never really played (the big one).** All three go through Perplexity, and not one of their 49 calls produced a usable answer. Every reply that came back was an empty `{}`. On buys, bids and trade replies, `{}` counted as an illegal decision and the rule-based bot decided. Before each roll it passed as "do nothing", so those three never built, mortgaged or offered a trade themselves. The runner was asking Perplexity for a JSON mode its docs don't offer (they document only a named JSON schema). It was also sending effort as a "preset", which Perplexity treats as a whole bundled agent setup; their prompts came out roughly 2,000 to 8,000 tokens longer than the other seats'. Nemotron, through the same API, answered 16 of 19.
2. **Perplexity hangs up after about a minute.** Grok thinks for longer than that at high effort. Perplexity closed the call each time, and three tries took 183 s before the bot stepped in (6 fallbacks). Other developers report the same one-minute cut-off.
3. **Your Mac's connection blipped** in rounds 2–3, and every API failed at once, most within about 4 s (6 fallbacks). Node gives each server address only 250 ms to connect, and your network's IPv6 has no route, so a moment of slow Wi-Fi fails everything at once.
4. **Perplexity's rate limit** hit twice in auctions, where its four seats bid at the same moment.

**What changed (v1.22)**
- Perplexity calls send effort the way Perplexity documents it, no preset and no JSON mode. The prompt already asks for JSON.
- Perplexity replies now stream, which should keep a long think from being cut off.
- An empty `{}` now counts as a failed answer, so it can't hide as "do nothing" again.
- Rate limits are waited out (as long as the server asks, or 4–32 s). A connection that never opened gets about 20 s of retries, and each address now gets 2.5 s instead of 250 ms.
- **Check the seats**, a new dashboard button (or `node runner/run.mjs --probe`), asks every model one real decision. Each seat shows ✓ with its answer, time and cost, or ✗ with why and what it replied. It costs a few cents and never touches the site.

**What to do on your Mac:** `git pull`, restart the dashboard, and press Check the seats before the next batch. The game running now keeps the old code until it ends. I couldn't reach Perplexity or the site from here, so the fix is built from Perplexity's documentation and this game's evidence and tested against a stand-in API. Check the seats is the real test: if ChatGPT, Grok or Kimi still shows ✗, paste me what it prints.

One thing I left alone: the game is slow. Qwen at high effort takes about 3 minutes a call (up to 7), and each auction waits for the slowest bidder. Eight rounds took nearly two hours. Lowering Qwen's effort is your call.

**Verified:** deploy dry run, engine simulation (0 illegal moves), replay and ledger checks, the provider checks with the new streaming and retry cases, two bot games plus a trading game into a fresh local site, all 95 browser checks, and the new button driven in a headless browser against a stand-in API.
